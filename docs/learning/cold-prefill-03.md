# 同镜像冷 Prefill：每轮预算 2048 → 4096 → 2048

2026-11-14，Atlas 300I DUO 双 310P3，`ychy-a2`。沿用[上一轮](cold-prefill-02.md)的 `bb0fa66f…` 镜像和现有 W8A8 权重，校验模型配置、分片索引及镜像内原始入口 SHA。每臂独立启动原入口，保持 TP2、262144 上下文、seq4、显存利用率 .90、主 Graph `[3,6,12]`、MTP2/draft eager、async 开启、prefix cache 关闭，唯一推理参数变量为 `max_num_batched_tokens`。

调度器用这一预算限制本轮所有请求，不改 GDN 内部 64-token 分块。预算加大可以减少分轮，但会影响启动激活预算、KV 容量和长短请求在同一轮的分配。本文仅讨论文本合成负载；没有覆盖生产前缀命中、图像/PDF 或正式延迟分位数。

依次通过 Graph / KV 池准入、短 JSON、32K 中段检索；随后测 C1 4K/32K 输入各预热一次、计时三次，各输出 1 token；C4 每轮同时发 1K/128、4K/256、8K/128、32K/256（输入/输出），连跑三轮。每臂复查短 JSON。固定同 token IDs、零前缀命中，普通计时禁用 profiler。C4 吞吐为从同时发起到最后一路完成的聚合输出吞吐；TPOT 来自客户端流式计时，混合了后续调度等待，不能看作纯 Decode kernel 时间。

| 测量中位数 | 2048 首轮 | 4096 | 2048 回测 | 4096 相对两个对照中位数的均值 |
|---|---:|---:|---:|---:|
| C1 4K TTFT，秒 | 1.994 | 1.830 | 2.001 | −8.36% |
| C1 4K Prefill，tok/s | 2,059.27 | 2,242.49 | 2,052.29 | +9.08% |
| C1 32K TTFT，秒 | 22.408 | 21.516 | 22.475 | −4.13% |
| C1 32K Prefill，tok/s | 1,463.36 | 1,524.14 | 1,459.28 | +4.30% |
| C4 聚合输出，tok/s | 17.51 | 18.48 | 17.54 | +5.46% |

4096 的三组 C4 都比两轮 2048 的六组快（18.19–18.54 vs 16.90–17.85 tok/s）。但交互有明确代价：1K/128 和 8K/128 在 4096 的三组中，每组两条流都出现约 3.79–3.86 秒的最长文本输出间隔；这两个形状在两轮 2048 对照中的最大值是 2.05 秒。此项是客户端连续有文本事件的间隔，不能当成单个 token 的 kernel 延迟。1K/4K 单独分层的 TTFT/TPOT 在两轮 2048 间漂移很大，不能用其中一个基线宣布短请求普遍改善或退化。8K/128 的 TTFT 中位为 32.22→4.01→30.04 秒，同时客户端 TPOT 中位为 50.27→256.69→70.46 ms。4096 更早给出首个响应，也留下更长的流式停顿；需要有序到达回放和更多样本才足以作交互采用判断。

三臂 18/18 条 C1、36/36 条 C4 计时请求有效，prefix hits 均为零；短 JSON 6/6，32K 中段检索 3/3。三臂报告 KV 池 636,277 / 636,277 / 636,903 tokens，启动报告的双芯片峰值激活均约 1.69–1.71 GiB。此处只核验准入余量，没有重跑 262K 满长或测请求期分配峰值。三臂退出码 0，无 OOM；`EngineDeadError` 各 1 条，均在成功完成最后一次 JSON 后、主动停机日志中。独立 SSH 已确认两种 Podman 作用域均无运行容器、设备无进程、端口和锁释放；没有操作 a1。

**采用建议：2048 继续作为交互通用默认，4096 保留为单流冷文本或吞吐优先的候选。** 下一轮优先冻结外部到达顺序，复测带 prefix cache 的业务请求并把最大文本间隔单列。若要兼顾吞吐与交互，可在独立实验里验证限制单次长 Prefill 分配的调度参数；需要先确认镜像实际生效。再采一条 32K 对照 timeline，按调度块检查分页 Attention、MoE 两个矩阵乘和布局转换的耗时，避免靠 4K 结果选择长输入 kernel。

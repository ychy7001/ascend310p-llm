# TP1/48G 实验 Profile

本文固定当前 Qwen3.6-35B-A3B 单卡 310P、W4A8、动态 C8、Decode Graph 的启动入口。业务目标是 `long-prefill`；`compat` 和 `decode` 保留为内部诊断及回归对照，避免 MindIEQ 修复后无法识别 Decode、MTP 或 Graph 的回归。profile 固定调度和已测后端组合，不改变权重或算子制品。参数解析集中在 `configs/tp1-profile.sh`，`--check` 和真正启动共用。

| profile | MTP | speculative tokens | Graph capture | batched tokens 默认值 | 适用场景 |
| --- | ---: | ---: | --- | ---: | --- |
| `compat` | 1 | 1 | `1,2` | 1024 | 兼容性基线、问题定位、MTP1 对照 |
| `decode` | 2 | 2 | `1,2,3` | 4096 | 当前单流 Decode 候选 |
| `long-prefill` | 2 | 2 | `1,2,3` | 4096 | 对外长上下文档；必须启用 MindIEQ，短输入按阈值回退 |

`mtp1` 和 `mtp2` 仍作为旧命令的兼容别名，分别映射到 `compat` 和 `decode`。当前配置默认仍为 `decode`，对应已经验证的 TP1/48G 112K 服务；只有完成 MindIEQ 修复、长上下文 P50/P95、质量和 Decode 门禁后，才将默认值切换为 `long-prefill`。

## 启动与校验

先准备 `MODEL_DIR`、`OPP_DIR`、`EXTENSION`、`C8_LIBRARY`、`GDN_OPP_DIR`、`GDN_LIBRARY` 和 `GDN_SOURCE`，再执行：

```bash
scripts/run-candidate.sh --check --profile compat
scripts/run-candidate.sh --check --profile decode
QWEN36_MINDIEQ_ENABLED=1 \
QWEN36_MINDIEQ_MIN_TOKENS=128 \
scripts/run-candidate.sh --check --profile long-prefill
```

校验输出包含规范化 profile 名称、解析后的 `effective_config`、权重索引和所有动态库的 SHA256。真正启动时去掉 `--check`。`long-prefill` 必须显式开启 MindIEQ；自动选择已测 E5 的自定义 A8、Gate/Up 共享量化和默认阈值128，不允许关闭这两个 E5 特性，且阈值不能低于128；不启用 MindIEQ 的同参数服务统一使用 `decode` 档作为内部对照。

## 选择原则

`compat` 用于回归和故障隔离，避免把 MTP2 的接受率或 Graph capture 问题混入算子判断。`decode` 是原始 W4 的内部运行基线，优先观察单流 TPOT、MTP 接受长度和稳定性。`long-prefill` 是业务候选，必须启用 MindIEQ，并同时通过长输入 P50/P95、TTFT/TPOT、完整质量集、needle 正确性和服务生命周期门禁，不能仅凭短请求收益替代端到端验收。收束后对外只保留 `long-prefill` 启动档，但保留两个诊断档的代码路径。

每个 profile 都保持 `MAX_MODEL_LEN=114688`、`MEMORY_UTILIZATION=0.95`、动态 C8 和 Decode Graph；长上下文容量需要结合实际 KV 分配、请求生命周期和 P95 结果单独记录。

## 不初始化 NPU 的回归校验

```bash
python3 tools/check_profile_launch.py
```

该工具使用临时占位制品和捕获参数的 Podman 替身，验证 `effective_config` 与真正启动入口构造的容器参数一致，并拒绝不满足 E5 约束的 `long-prefill` 配置。它只验证参数传递，不证明占位制品可加载，也不替代真实设备启动。

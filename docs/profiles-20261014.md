# TP1/48G 实验 Profile

本文固定当前 Qwen3.6-35B-A3B 单卡 310P、W4A8、C16/C8、Decode Graph 的启动入口。唯一默认业务档为 `long-prefill`；`compat` 和 `decode` 保留为内部诊断及回归对照，避免 MindIEQ 修复后无法识别 Decode、MTP 或 Graph 的回归。profile 固定调度和已测后端组合，不改变权重或算子制品。参数解析集中在 `configs/tp1-profile.sh`，`--check` 和真正启动共用。

| profile | MTP | speculative tokens | Graph capture | batched tokens 默认值 | 适用场景 |
| --- | ---: | ---: | --- | ---: | --- |
| `compat` | 1 | 1 | `1,2` | 1024 | 兼容性基线、问题定位、MTP1 对照 |
| `decode` | 2 | 2 | `1,2,3` | 4096 | 当前单流 Decode 候选 |
| `long-prefill` | 2 | 2 | `1,2,3` | 4096 | 对外长上下文档；必须启用 MindIEQ，短输入按阈值回退 |

`mtp1` 和 `mtp2` 仍作为旧命令的兼容别名，分别映射到 `compat` 和 `decode`。当前候选入口默认选用 `long-prefill`，自动启用 E5 的自定义 A8、Gate/Up 共享和阈值128短请求回退。这是长上下文实验候选的默认选择，完整业务质量、并发和尾延迟门禁仍待完成。旧 C8/GDN wrapper 保留显式基线参数用于诊断，不作为业务推荐入口。

## 启动与校验

先准备 `MODEL_DIR`、`OPP_DIR`、`EXTENSION`、`C8_LIBRARY`、`GDN_OPP_DIR`、`GDN_LIBRARY`、`GDN_SOURCE` 和 `MINDIEQ_LIBRARY`，再执行：

```bash
scripts/run-candidate.sh --check  # 唯一默认业务档 long-prefill
scripts/run-candidate.sh --check --profile compat  # 内部MTP1对照
scripts/run-candidate.sh --check --profile decode  # 内部原W4对照
```

校验输出包含规范化 profile 名称、解析后的 `effective_config`、权重索引和所有动态库的 SHA256。真正启动时去掉 `--check`。`long-prefill` 默认开启 MindIEQ，显式关闭会被拒绝；自动选择已测 E5 的自定义 A8、Gate/Up 共享量化和默认阈值128，不允许关闭这两个 E5 特性，且阈值不能低于128；不启用 MindIEQ 的同参数服务统一使用 `decode` 档作为内部对照。

## 选择原则

`compat` 用于回归和故障隔离，避免把 MTP2 的接受率或 Graph capture 问题混入算子判断。`decode` 是原始 W4 的内部运行基线，优先观察单流 TPOT、MTP 接受长度和稳定性。`long-prefill` 是业务候选，必须启用 MindIEQ，并同时通过长输入 P50/P95、TTFT/TPOT、完整质量集、needle 正确性和服务生命周期门禁，不能仅凭短请求收益替代端到端验收。对外只推荐 `long-prefill` 启动档，保留两个诊断档的代码路径。必需设置 `MINDIEQ_LIBRARY`，校验器会记录其SHA256；缺失时拒绝启动，不静默回退到另一档。

每个 profile 都保持 `MAX_MODEL_LEN=114688`、`MEMORY_UTILIZATION=0.95`和 Decode Graph；公开48G/112K入口默认C16，`QWEN36_C8_ENABLED=1`可覆盖；长上下文容量需要结合实际 KV 分配、请求生命周期和 P95 结果单独记录。

## 不初始化 NPU 的回归校验

```bash
python3 tools/check_profile_launch.py
```

该工具使用临时占位制品和捕获参数的 Podman 替身，验证 `effective_config` 与真正启动入口构造的容器参数一致，并拒绝不满足 E5 约束的 `long-prefill` 配置。它只验证参数传递，不证明占位制品可加载，也不替代真实设备启动。

## 2026-10-15 KV默认值更新

a2/EP310P3的MTP2配对与clt/EP310P1的MTP1独立测试均显示，112K下C8的Decode代价明显，而按相同调度容量核算净省约1GiB。48G/112K公开入口因此优先C16，保留C8实验后端。详细样本、接受率、实际预留池与估算边界见[a2记录](../results/a2-kv-comparison-20261015/README.md)。旧实验wrapper保持原默认用于历史复现，必须从`run-candidate.sh --check`确认有效参数，不能靠服务名判断KV格式。RC另行验证，不自动继承EP的KV和MTP默认值。

# TP1/48G 实验 Profile

本文固定当前 Qwen3.6-35B-A3B 单卡 310P、W4A8、动态 C8、Decode Graph 的启动入口。profile 只选择调度和验收边界，不改变权重、算子制品或服务端默认行为。

| profile | MTP | speculative tokens | Graph capture | batched tokens 默认值 | 适用场景 |
| --- | ---: | ---: | --- | ---: | --- |
| `compat` | 1 | 1 | `1,2` | 1024 | 兼容性基线、问题定位、MTP1 对照 |
| `decode` | 2 | 2 | `1,2,3` | 4096 | 当前单流 Decode 候选 |
| `long-prefill` | 2 | 2 | `1,2,3` | 4096 | 长上下文 Prefill，MindIEQ 可选 |

`mtp1` 和 `mtp2` 仍作为旧命令的兼容别名，分别映射到 `compat` 和 `decode`。默认配置为 `decode`，对应当前已验证的 TP1/48G 112K 服务。

## 启动与校验

先准备 `MODEL_DIR`、`OPP_DIR`、`EXTENSION`、`C8_LIBRARY`、`GDN_OPP_DIR`、`GDN_LIBRARY` 和 `GDN_SOURCE`，再执行：

```bash
scripts/run-candidate.sh --check --profile compat
scripts/run-candidate.sh --check --profile decode
QWEN36_MINDIEQ_ENABLED=1 \
QWEN36_MINDIEQ_MIN_TOKENS=128 \
scripts/run-candidate.sh --check --profile long-prefill
```

校验输出包含 profile 名称、权重索引和所有动态库的 SHA256。真正启动时去掉 `--check`。`long-prefill` 只有在开启 MindIEQ 时才强制要求最小 Prefill token 阈值不低于 128；不启用 MindIEQ 时仍可作为 MTP2 长上下文对照。

## 选择原则

`compat` 用于回归和故障隔离，避免把 MTP2 的接受率或 Graph capture 问题混入算子判断。`decode` 是当前业务候选，优先观察单流 TPOT、MTP 接受长度和稳定性。`long-prefill` 只在完成长输入 P50/P95 后用于比较 MindIEQ 的 Prefill 收益，不能仅凭短请求收益替代端到端验收。

每个 profile 都保持 `MAX_MODEL_LEN=114688`、`MEMORY_UTILIZATION=0.95`、动态 C8 和 Decode Graph；长上下文容量需要结合实际 KV 分配、请求生命周期和 P95 结果单独记录。

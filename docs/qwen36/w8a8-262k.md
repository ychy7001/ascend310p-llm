# W8A8 TP2 + native WY + MTP2：镜像拉取与逐步复现

在两张 310P3 上跑 Qwen3.6-35B-A3B 的满上下文配置。全部步骤用固定 digest 的已发布镜像，**不需要编译算子、不需要挂载宿主源码**。

配置选择依据、完整验收记录与限制见[满上下文部署配置](wy-mtp-production-20261108.md)；档位对照见 [deploy/README.md](../../deploy/README.md)。

## 前置条件

| 项目 | 要求 |
| --- | --- |
| 硬件 | 两张 Atlas 300I DUO（Ascend 310P3），同机 |
| 驱动 | 已在 a2 验证的是 26.1.1；a1 现为 26.0.rc1，未在该版本上验收 |
| CANN | 9.1.0-beta.1（镜像自带，宿主装驱动即可） |
| 运行时 | rootless Podman，或 Docker（需自行调整设备与用户映射，仓库未验证） |
| 权重 | Qwen3.6-35B-A3B 的 W8A8 权重，宿主目录形式 |
| 磁盘 | 权重之外预留镜像空间；镜像已含 CANN 与已测算子 |

## 1. 拉取镜像

```bash
podman pull registry.cn-hangzhou.aliyuncs.com/meetai/llm-service-vllm-ascend@sha256:ed57fbefba5c1631e16be53ac30baf08f091b24fb8c0e8f4799ba6231e76c1aa
```

用 digest 拉取，不要用 tag。已发布 tag 为 `qwen36-tp2-w8a8-wy-mtp2-20261108`，但部署引用一律写 digest。

## 2. 核验镜像身份

确认拉到的镜像配置与验收时一致：

```bash
IMAGE=registry.cn-hangzhou.aliyuncs.com/meetai/llm-service-vllm-ascend@sha256:ed57fbefba5c1631e16be53ac30baf08f091b24fb8c0e8f4799ba6231e76c1aa

# 入口必须是镜像内路径，不能被宿主覆盖
podman inspect --format '{{json .Config.Entrypoint}}' "$IMAGE"
# 期望：["bash","/opt/qwen36/start-wy-mtp.sh"]

# 镜像内自带 manifest 与启动脚本
podman run --rm --network=none --entrypoint cat "$IMAGE" /opt/qwen36/wy-mtp-manifest.json
```

验收时的 image ID 为 `bb0fa66f1c715a94abf56afc17a6bd02e3f993c4804e200dfd229e22b0d5cab`。registry 侧 manifest 与 config 摘要已核验过与该 ID 一致。

镜像内含 PR18730 配套的 recurrent 状态表修复（Python wrapper、host、kernel 必须成套使用，不能只替换 wrapper），以及把 MTP slot block IDs 在乘法前提升到 int64 的兼容补丁。

## 3. 准备环境文件

```bash
cp deploy/w8a8-tp2-wy-mtp/qwen36-wy-mtp-image.env.example ~/.config/qwen36-wy-mtp.env
```

改 `MODEL_DIR` 为宿主上的 W8A8 权重绝对路径。其余值就是验收过的配置，不要随手改：

| 变量 | 值 | 说明 |
| --- | --- | --- |
| `MAX_MODEL_LEN` | `262144` | 输入 + 输出总上限 |
| `MAX_BATCHED_TOKENS` | `2048` | |
| `MEMORY_UTILIZATION` | `0.90` | |
| `MAX_NUM_SEQS` | `4` | 调度并发上限，不是驻留承诺 |
| `NUM_SPECULATIVE_TOKENS` | `2` | |
| `ENFORCE_EAGER` | `0` | 主模型开 Graph |
| `DRAFT_ENFORCE_EAGER` | `1` | draft 走 eager，实测比双 Graph 快 |
| `GRAPH_CAPTURE_SIZES` | `3,6,12` | 310P event 资源有限，捕获档位要收敛 |
| `ENABLE_PREFIX_CACHING` | `1` | 生产默认；冷 Prefill 测试用独立 cache salt 避免命中 |
| `ASYNC_SCHEDULING` | `1` | |

宿主模型路径会以只读方式挂到容器 `/model`。**不要把宿主路径当容器模型路径填**——`qwen36-wy-image.service` 会把容器内 `MODEL_DIR` 覆盖为 `/model`。

## 4. 起服务

先确认设备空闲：

```bash
npu-smi info          # 无残留进程
podman ps             # 无同设备容器在跑
```

再启动。首次起服务要加载权重并做 Graph 捕获，视权重读取速度需要数分钟。

```bash
podman run -d \
  --name qwen36-wy-mtp \
  --network host \
  --group-add keep-groups \
  --ipc shareable --shm-size 32g \
  --device /dev/davinci0 --device /dev/davinci1 \
  --device /dev/davinci_manager --device /dev/devmm_svm --device /dev/hisi_hdc \
  -v /usr/local/bin/npu-smi:/usr/local/bin/npu-smi:ro \
  -v /etc/ascend_install.info:/etc/ascend_install.info:ro \
  -v /usr/local/Ascend/driver/version.info:/usr/local/Ascend/driver/version.info:ro \
  -v /usr/local/Ascend/driver/lib64:/usr/local/Ascend/driver/lib64:ro \
  -v /usr/local/dcmi:/usr/local/dcmi:ro \
  -v "$MODEL_DIR":/model:ro \
  --env-file ~/.config/qwen36-wy-mtp.env \
  "$IMAGE"
```

长期运行用 Quadlet：把 `deploy/w8a8-tp2-wy-mtp/qwen36-wy-mtp-production.container` 里宿主相关的路径与设备改成目标机实际值，再安装。

## 5. 验证

依次做四件事，任何一步失败就停下看日志，不要继续。

```bash
BASE=http://127.0.0.1:18025

# 5.1 健康
curl -sS "$BASE/health"

# 5.2 基本生成
curl -sS "$BASE/v1/chat/completions" -H 'Content-Type: application/json' -d '{
  "model": "Qwen3.6-35B-A3B-w8a8",
  "messages": [{"role":"user","content":"Reply with exactly: OK."}],
  "max_tokens": 16
}'

# 5.3 冷文本 Prefill（4K / 32K）。--cache-salt-prefix 让每条请求用不同 salt，
#     结果里 prefix hits 必须为 0，否则测的是缓存命中而不是冷 Prefill
python3 tools/bench_server_phases.py --base-url "$BASE" \
  --model Qwen3.6-35B-A3B-w8a8 --prompt-tokens 4096 --output-tokens 1 \
  --repeats 1 --cache-salt-prefix cold-4k --out /tmp/prefill-4k.json

python3 tools/bench_server_phases.py --base-url "$BASE" \
  --model Qwen3.6-35B-A3B-w8a8 --prompt-tokens 32768 --output-tokens 1 \
  --repeats 1 --cache-salt-prefix cold-32k --out /tmp/prefill-32k.json

# 5.4 Decode
python3 tools/bench_http_stream.py --base-url "$BASE" \
  --model Qwen3.6-35B-A3B-w8a8 --prompt-tokens 4096 --output-tokens 128 \
  --concurrency 1 --repeats 1 --out /tmp/decode.jsonl
```

计时含 HTTP 与调度开销，是服务侧阶段吞吐，不是纯 kernel 时间。

参考量级（a2 实测，每档三次取中位，prefix hits 均为 0）：

| 冷输入 | Prefill tok/s | TTFT 秒 |
| ---: | ---: | ---: |
| 4K | 2049.6 | 2.002 |
| 32K | 1456.7 | 22.512 |

4K 输入 / 128 输出 decode 约 45.9 tok/s，MTP 接受率约 85%。明显低于这个量级时先查驱动版本、是否有其他进程占卡、`GRAPH_CAPTURE_SIZES` 是否被改过。

## 6. 边界：这些通过不等于什么

复现这几步只证明**服务能起、能算、容量与执行完整**。以下都不由上面的检查覆盖：

- **容量通过不等于 262K 语义质量通过**。`262016 + 128` 能完整返回、超限请求正确返回 400，只说明 KV 容量与调度能容纳，不说明长上下文检索准确率。
- **PDF 功能通过不等于正式 OCR 非劣效**。四页 PDF 的功能检查是 smoke，公开集上的成对评测规模也小，中文票据未评估。
- **seq4 是调度上限，不承诺四条 262K 请求同时驻留**。启动报告 KV pool 约 635026 tokens，即约 2.42 条满上下文请求，超出部分由调度器排队。
- 所有性能数字是固定协议单流或指定并发下的服务侧测量，不是 P95。
- a1 尚未切换，本页不构成 a1 部署授权。

## 7. 回滚

回滚到 W4A8 TP1 稳定档：

1. 停当前容器并移除。
2. 确认 NPU 无进程、两服务 inactive。
3. **冷却至少 60 秒**（310P CANN TBE 初始化的既有观测，必须执行）。
4. 用 `deploy/w4a8-tp1/` 的入口与既已验证 digest 启动。
5. 要求 `/health` 加一次正常生成。

回滚同样执行完整冷却，不做即时镜像互换。

## 8. 出问题先看哪里

| 现象 | 先查 |
| --- | --- |
| 启动后模型图捕获失败，栈里有 `query_start_loc.to("cpu")` | 用的是不带兼容层的旧镜像；W8 MTP 必须用本页 digest |
| 捕获失败指向 `attn_update_stack_num_spec_norm` 的 int32 `Mul` | slot index 补丁未生效，镜像不对 |
| Graph 捕获时 event 资源耗尽 | `GRAPH_CAPTURE_SIZES` 被放大；310P 上不要用全档位 |
| `/model` 下找不到权重 | 宿主路径填成了容器路径，或挂载被 service 覆盖 |
| 长时间无输出但进程在 | 权重读取阶段，看容器日志确认进度 |

Graph 兼容性问题的定位过程：旧栈 SplitFuse mask 的 CPU 拷贝在捕获中被禁止，改为在 Graph 外维护固定 NZ mask 缓冲区、捕获内只返回该缓冲区，每次 replay 刷新内容。详见 [mask 兼容修复](wy-mtp-mask-fix-20261108.md) 与 [Graph 定位](wy-mtp-graph-localization-20261108.md)。

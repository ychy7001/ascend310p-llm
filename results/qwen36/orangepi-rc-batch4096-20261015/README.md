# orangepi RC：Prefill 分块 2048 → 4096

固定 TP1/W4A8/MTP1/C8/GDN/MindIEQ/Decode Graph、max_model_len=114688、标称 KV 预算 6GiB、同步调度和 prefix 开启，仅修改 max_num_batched_tokens。比较对象是 `../orangepi-rc-baseline-20261015/` 的 2048 档，同输入 SHA、固定输出 128、每轮独立 cache salt，prefix 命中均为 0。

| 输入 | 2048 Prefill | 4096 Prefill | 变化 | 2048 Decode | 4096 Decode |

| 8192 | 563.62 | 625.90 | +11.05% | 23.87 | 23.90 |

单位 tok/s；各 warmup 1 + 正式 3 轮，中位数。Decode 差异 <0.4%，不能据此声称加速。8192 档一轮 MTP 接受率 86.76%，其余为 100%；相较 2048 的输出仅 2/3 逐字一致，32768 为 3/3。分块导致数值/生成路径变化，尚无正式精度评测。

最小质量门禁：8题8/8、A/B/A重复一致且无 canary 串扰。单次 112000-token 合成会议决议更新检查通过，记录位于输入约10%/50%/90%，输出54 tokens，prefix 0命中，Prefill 377.24、Decode 11.60 tok/s，MTP接受率100%。该样本与固定输出测速不同，不用于直接计算2048/4096长上下文加速比，也不代表正式质量或P95。

`summary.json`、`p*-o128.jsonl` 为配对统计及原始记录，`meeting-112000.json` 与压缩 token-ID 为长上下文检查结果和复现输入，`env.json` 与日志记录环境。4096 已通过上述局部门禁，可用于后续 C16/C8 比较；最终部署仍需长上下文与内存取舍。

仅去掉逐行UT中row/sub的两个clone，保留全部算术顺序。固定rank0-call0001的q/k/w/u/g逐位一致，但三次计时下完整WY由6.3905ms增至6.7541ms，候选/基线时延比约1.057，未见扩大测试的依据。

## 3. 阶段耗时定位：逐行UT是调度优化的优先对象

从同一冻结模块以AST提取helper，只添加阶段同步计时。两组真实输入的全部输出均逐位一致；128/640 token时UT循环同步计时中位数约7.17/7.52ms。阶段边界的同步改变执行调度，这些阶段时间不能相加推算生产耗时，亦不能与其他窗口计时直接比较。

## 4. TorchScript逐行UT：固定612组基线等价复核通过

保留原63轮逐行FP32运算、两处clone和归约表达式，仅由TorchScript执行UT函数。短诊断中同一真实输入五项输出逐位相同，完整WY从7.1355ms降为6.5565ms，速度比1.0883；基线先测、候选后测且只覆盖一个输入，该数字不是性能门禁或端到端收益。

# W4A8 + FP16 KV 并发备选（2026-10-14）

## 配置

- a2 chip1、独立端口 18026；chip0/18024 未修改
- Qwen3.6-35B-A3B W4A8，TP1
- **C8 关闭，FP16 KV**；GDN PR #17640 开启；MTP2 开启
- eager（无 Decode Graph），`max_num_seqs=8`，`max_num_batched_tokens=4096`
- prefix cache 关闭
- 请求：512 prompt / 32 completion，warmup 1，正式 3 轮；每轮所有并发请求同时发送

## 结果

| 并发 | 总输出 tok/s（三轮） | 中位总吞吐 | TTFT 中位 | TPOT 中位 |
|---:|---:|---:|---:|---:|
| 2 | 19.732 / 19.882 / 19.873 | **19.873** | 2.131 s | 35.098 ms |
| 4 | 23.790 / 23.697 / 23.884 | **23.790** | 4.097 s | 41.397 ms |
| 8 | 25.223 / 25.227 / 25.254 | **25.227** | 8.084 s | 66.278 ms |

所有请求均返回完整 usage，c=2/4/8 分别完成 6/12/24 个正式请求；服务没有崩溃。原始 HTTP 结果保存在本目录三个 JSONL 文件中。

## 判断

关闭 C8 后，W4A8 后端可以承受 `max_num_seqs=8`，说明上一轮错误来自 C8 adapter 的单请求 storage 假设，而不是 W4A8 模型或 vLLM 调度器的普遍限制。并发增加时总吞吐从约19.9提升到25.2 tok/s，但 TTFT 和 TPOT明显上升；这是短输入/短输出 eager 压力探针，不能替代长 Prefill 的业务吞吐。

该路径的代价是放弃 C8 的 KV 显存节省和长上下文容量，不能与 112K C8 单流候选合并成一个规格。建议保留两种产品模式：C8/单流/112K，以及 FP16 KV/并发/较短上下文；后者还需要按目标上下文长度补充显存和长 Prefill 门禁。

## 单流 32K/128 长 Prefill

同一 FP16 KV 服务执行 32256 token、128 输出，warmup 1 + 正式 3 次：

| 指标 | 三次结果 | 中位数 |
|---|---:|---:|
| Prefill tok/s | 453.303 / 453.424 / 453.239 | **453.303** |
| Decode tok/s | 29.126 / 29.130 / 29.111 | **29.126** |

三次均通过 counter/usage 校验；MTP 每次 43 drafts、86 drafted、86 accepted，接受率100%，平均接受长度3。当前 FP16 KV 服务启动时设置 `max_model_len=32768`，因此本结果只能证明 32K 备选档位，不能外推到更长上下文。

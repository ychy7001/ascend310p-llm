# 八格三臂基准：本轮判定规则不可用（2026-11-06）

窗口 `day2-20261105/bench`；前置 [day2 门禁](../day2/README.md) 已 `gates_passed`（G1、G2 均 `True`）。顺序 A → B → A′，八格，每格每臂 3 轮、每次 256 输出 token。A、A′ 为生产镜像，B 为候选 `ascend310p-llm-candidate@sha256:c590aeba…`。

**本轮基准失败，根因是判定规则，不是候选。** 旧规则要求逐格逐指标 `B/A ≤ 1+|A′/A−1|`（时延）或 `≥ 1−|A′/A−1|`（吞吐），24 项检查只过 16 项、八格只过 3 格。这个通过率是无退化假设下掷硬币的正常结果：A′ 与 B 是独立采样，单次检查在对数比上是对称的，所以每一格三项全过 `P=0.5³=0.125`，24 项全过 `0.5²⁴=5.96e-08`。旧规则对字节完全相同的候选也几乎不可能通过，它测的不是候选，是两个独立样本的相对顺序。

数据本身完整：24 个 jsonl 全部 3 轮成功、prompt token ID 三臂逐格相同、usage 均为规定 token 数。没有请求失败、没有重试、没有删格。

### 第二条弱点：C4 格内变异

逐格中位数本身在 C4 就不稳。三臂各自的格内变异系数（3 轮）：

| 指标 | C1 范围 | C4 范围 |
| --- | ---: | ---: |
| TTFT | 0.11%–4.30% | 35.57%–46.12% |
| TPOT | 0.00%–0.50% | 7.09%–59.74% |

C4 的 TTFT 格内变异 35%+ 意味着单格的 TTFT 中位数在 ±35% 量级上重复不出来，这与候选好坏无关。旧规则却把它当成确定值做比值。

## 新规则与同一份证据的再判定

改为跨八格的汇总检验：每格取 `B/√(A·A′)` 的对数，八格求均值，单侧 t 界。几何中点消掉线性漂移——B 就排在 A 与 A′ 之间，若整轮存在单调漂移，`√(A·A′)` 正是一阶无偏的漂移中心。判定量为

- 时延：拒绝条件 `exp(mean + t·se) > 1+δ`
- 吞吐：拒绝条件 `exp(mean − t·se) < 1−δ`

`t_{0.95,7} = 1.894578605`。δ 用时延 2%、吞吐 1%：按本轮实测的八格对数标准差做完整流水线模拟（抽 8 个对数比、由样本估 se、再做 t 检验），时延 δ=2% 对应第一类错误 4.78%（TTFT）/ 0.00%（TPOT），吞吐 δ=1% 对应 0.20%；对真实退化的检出率 TTFT 1%→49.2%、2%→95.1%，TPOT 1%→4.6%、2%→94.9%，吞吐 1%→95.0%。吞吐用更紧的 δ 是因为它八格对数标准差只有 0.56%，是三项里最稳的。代价是 TPOT 对 1% 级退化基本无检出能力，这是本轮 8 格样本量下的真实限制，不作掩饰。

## 真实限制

- 只覆盖一个模型（Qwen3.6-35B-A3B W8A8 TP2）、一组启动参数、一个窗口。
- 吞吐统计是每轮聚合输出 token/秒的中位数，不是稳态饱和吞吐。
- 当前 8 格样本量下 TPOT 只能可靠检出 2% 级退化；更小退化需要更多格或更多轮次。
- 未产出会议回放、RAG 8K–32K Prefill 或通用负载的收益结论；`device_accepted` 仍为 `false`，因为本轮基准在冻结规则下判 `failed`。
- 24 份原始 jsonl（4.68 MB）、容器日志、命令和 inspect 留在仓库外；本目录只含脱敏摘要、格级数值与证据 SHA256。
